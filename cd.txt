# Phase 3 Plan: Covertype Background-Aware InstaSHAP Extension

**Summary**
- Build a fully standalone Phase 3 project inside `C:\Users\RAVIPRAKASH\Downloads\X_AI-Project\Phase_3_work` that reproduces the current InstaSHAP-style Covertype pipeline and then extends it with one research improvement.
- Use **Covertype** as the single primary dataset, because the current code already encodes a strong `elevation × soil_climate_zone` dependence signal and the existing reproduced Covertype InstaSHAP result is weak enough to support a meaningful “before vs after” story.
- Define the research gap as: **the current implementation uses zero-masking in transformed feature space (`x * mask`), which creates unrealistic masked samples for tabular data, especially with standardized numeric features and one-hot categorical groups; this can damage surrogate fidelity, downstream InstaSHAP quality, and explanation faithfulness.**
- Implement one improvement: **Empirical-Background Masking InstaSHAP**.
  - Baseline: current zero-mask coalition construction.
  - Improved method: replace every masked original feature group with values copied from real training rows, and average surrogate targets over multiple sampled background rows per coalition.
  - Framing: this is a data-aware approximation to marginal/interventional masking, supported by the original paper’s discussion of baseline/marginal/conditional removal choices and by prior literature showing that independence-style or off-distribution masking can give wrong explanations.
- Evaluate the extension with a strict **baseline vs improved** comparison on the same dataset, same seeds, same architecture family, same train/val/test protocol, and same reporting pipeline.
- Final deliverables will be generated from the code itself: runnable program, results tables/plots in the repo, updated `README.md`, `AI_USAGE.md`, multi-page experiment PDF, and a separate 1-page research-gap PDF.

**Implementation Changes**
- Create a standalone Phase 3 package under `Phase_3_work`, with copied/adapted Phase 2 code so the final project does not depend on importing Phase 2 at runtime.
- Keep the core structure recognizable: `data/`, `models/`, `training/`, `experiments/`, `utils/`, `reports/`, `results/`, `docs/`, plus root `README.md`, `requirements.txt`, and `AI_USAGE.md`.
- Reuse the same Covertype loader logic from Phase 2 so dataset definition stays aligned with the paper and with the provided `loaders.py`.
- Introduce a masking abstraction with two explicit strategies:
  - `zero_mask`: exact baseline behavior from the current project.
  - `empirical_background`: for each sampled coalition mask, fill masked original feature groups from sampled training rows instead of zeroing transformed columns.
- Add a new small config/type layer, for example `MaskingConfig`, with fixed fields:
  - `strategy`
  - `background_bank_size`
  - `background_samples_train`
  - `background_samples_eval`
  - `seed`
- Extend preprocessing utilities so masking happens at the **original feature-group level**, not raw transformed-column multiplication only.
  - Numeric groups remain valid scalars.
  - One-hot categorical groups are replaced as a whole group from a real encoded training row, preserving one-hot validity.
- Update surrogate training:
  - Baseline run keeps current zero-mask objective.
  - Improved run builds masked inputs via empirical-background replacement.
  - Surrogate targets for the improved run are averaged across `K` sampled background rows per input/mask to reduce variance and better approximate the masked value function.
- Update InstaSHAP training:
  - Train one baseline InstaSHAP model against the zero-mask surrogate.
  - Train one improved InstaSHAP model against the empirical-background surrogate.
  - Keep architecture, optimizer family, patience, and interaction settings matched so the comparison isolates the masking change.
- Keep Covertype interaction modeling fixed to the current pair `("elevation", "soil_climate_zone")` for both baseline and improved variants.
- Add experiment naming that is impossible to confuse:
  - `instashap_zero`
  - `instashap_bg`
  - `surrogate_zero`
  - `surrogate_bg`
- Extend result schemas so Phase 3 always emits:
  - predictive metrics table
  - explanation fidelity table
  - coalition fidelity table
  - runtime table
  - seed aggregate JSON
  - plots for metric comparison and explanation comparison
- Add a report generator script that reads produced CSV/JSON/PNG artifacts and creates:
  - `reports/phase3_experiment_report.pdf`
  - `reports/phase3_research_gap_1page.pdf`
- Add Markdown companions for both PDFs so the textual content is easy to review in the repo:
  - `reports/phase3_experiment_report.md`
  - `reports/phase3_research_gap_1page.md`

**Experiment Design**
- Run one smoke test with `--fast-dev-run` to validate the whole pipeline before full execution.
- Run the full experiment with **3 seeds** to make the PDF academically stronger than a single lucky run.
- Keep train/val/test split logic identical across baseline and improved variants within each seed.
- Compare these models in every seed:
  - black-box baseline
  - GAM-1
  - GAM-2
  - `instashap_zero`
  - `instashap_bg`
- Main quantitative tables:
  - predictive performance: accuracy and log-loss
  - explanation fidelity vs permutation SHAP: MSE, MAE, and rank correlation
  - runtime: training time, one-pass explanation time, SHAP total explanation time
  - coalition fidelity: surrogate error on held-out masked evaluations for zero-mask vs background-mask objectives
- Main qualitative figures:
  - metric bar chart for predictive performance
  - explanation fidelity comparison chart
  - latency comparison chart
  - SHAP vs `instashap_zero` alignment plot
  - SHAP vs `instashap_bg` alignment plot
  - improved model shape plots for `elevation`, `soil_climate_zone`, `aspect`
  - improved interaction heatmap for `elevation × soil_climate_zone`
- The report claim will be considered successful if:
  - `instashap_bg` improves explanation fidelity over `instashap_zero` on most seeds
  - predictive accuracy is preserved or improved relative to `instashap_zero`
  - the report clearly shows why the change is attributable to better masking, not a larger model or looser setup
