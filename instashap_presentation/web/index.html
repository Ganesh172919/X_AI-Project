⚙️ Core

How InstaSHAP Approximates

Traditional Shapley Computation

φᵢ = Σ |S|!(n-|S|-1)!/n! × [f(S∪{i}) - f(S)]

Sums over ALL subsets S ⊆ N\{i}
→ 2ⁿ⁻¹ evaluations per feature
→ n × 2ⁿ⁻¹ total model calls

InstaSHAP Approximation

φ̂ᵢ ≈ (1/k) Σⱼ₌₁ᵏ [f(Sⱼ∪{i}) - f(Sⱼ)]

Samples only k random subsets
→ k evaluations per feature (k ≪ 2ⁿ)
→ n × k total model calls

Key Insight: With k = 50 and n = 20, InstaSHAP uses 1,000 calls vs exact's 10,485,760

Step 2: Feature Perturbation Strategy

To measure feature importance, we mask/remove features and observe prediction changes

The Core Question

How much does prediction change when we remove each feature?

Perturbation Methods

Step 3 · Sampling

Step 3: Subset Sampling Strategy

InstaSHAP randomly selects k subsets instead of enumerating all 2ⁿ

  • 1 Generate k random binary masks (each mask = one subset)
  • 2 Each mask determines which features are "present" vs "absent"
  • 3 Uniform random sampling — no preference for any subset size
Step 3 · Math

Sampling: The Mathematical View

Random Mask Generation

for j = 1 to k: mask[j] = random_binary_vector(n) # e.g., [1, 0, 1] means # Age=present, Income=absent, Score=present S[j] = features where mask[j] = 1 x_perturbed[j] = replace absent features with training sample

What's approximated here

  • ⚠ Skipped: Shapley weighting factor |S|!(n-|S|-1)!/n!
  • ⚠ Assumed: Random subsets are representative of all subsets
  • ⚠ Bias risk: May over/under-represent certain subset sizes
  • ✓ Gain: O(k) instead of O(2ⁿ) evaluations

Step 4: Batch Model Prediction

Step 4 · Internal

What Happens Inside Each Forward Pass

For each perturbed input:

  • 1 Input vector enters layer 1 (3 nodes)
  • 2 Weights multiply, biases add → hidden layer 1
  • 3 ReLU activation applied
  • 4 Hidden layer 2 processes
  • 5 Sigmoid output → probability [0, 1]

Note: InstaSHAP treats the model as a BLACK BOX — only input/output matter, not internal weights

Step 5 · Contribution

Step 5: Marginal Contribution Estimation

For each feature, compute: "How much does adding this feature change the prediction?"

For feature i, using sampled subsets: φ̂ᵢ = (1/k) × Σⱼ [f(Sⱼ ∪ {i}) - f(Sⱼ)] (only subsets where i ∉ Sⱼ) Example for feature "Income" (i=2): Subset {Age}: f({Age,Income}) - f({Age}) = 0.70 - 0.53 = 0.17 Subset {Score}: f({Score,Income}) - f({Score}) = 0.76 - 0.56 = 0.20 Subset {}: f({Income}) - f({}) = 0.62 - 0.50 = 0.12 φ̂(Income) = average(0.17, 0.20, 0.12) = 0.163
Key approximation: Using k sampled subsets instead of all 2ⁿ⁻¹ subsets containing feature i
Step 5 · All Features

Computing All Feature Contributions

Feature contributions (averaged): φ̂(Age) = avg marginal when Age added = (0.03 + 0.08 + 0.06) / 3 = 0.057 φ̂(Income) = avg marginal when Income added = (0.17 + 0.20 + 0.12) / 3 = 0.163 φ̂(Score) = avg marginal when Score added = (0.06 + 0.15 + 0.11) / 3 = 0.107 Base value E[f(x)] ≈ 0.50 Sum: 0.50 + 0.057 + 0.163 + 0.107 = 0.827 ≈ 0.82 ✓

🔬 Deep Tech

Internal Mechanism: Mathematical Intuition

Exact Shapley Formula

φᵢ(f) = Σ_{S⊆N\{i}} |S|!(n-|S|-1)!/n! · [f(S∪{i}) - f(S)]

The weighting factor |S|!(n-|S|-1)!/n! ensures fairness — every possible ordering of features is considered equally.

InstaSHAP Monte Carlo

φ̂ᵢ ≈ (1/k) Σⱼ₌₁ᵏ w(Sⱼ) · [f(Sⱼ∪{i}) - f(Sⱼ)]

Monte Carlo sampling replaces the exhaustive sum with k random samples. Weights w(Sⱼ) approximate the Shapley kernel.

Key insight: By the law of large numbers, as k → ∞, φ̂ᵢ → φᵢ. But we want k to be small.

⚙️ Sampling Strategy

Sampling Strategy: Random vs Stratified

Random Uniform

Each subset drawn independently with equal probability. Simple but may miss important regions.

P(S selected) = 1/2ⁿ for all S
Default in InstaSHAP

Stratified (Improved)

Ensures representation across all subset sizes |S| = 0, 1, ..., n. Better coverage.

Sample k/n subsets of each size
Potential improvement
  • ⚠ Shapley values weight small and large subsets heavily — random may under-sample these
  • → Stratified sampling could reduce variance by 30-50% (see Phase 2 improvements)
⚠ Bias

Where Bias Enters

Sources of Approximation Bias

  • 1 Sampling bias: Random subsets may not cover all important coalitions
  • 2 Marginal perturbation bias: Replacing features with random samples assumes feature independence
  • 3 Finite sample error: With small k, average may not converge to true expectation
  • 4 Weight approximation: Shapley kernel weights are simplified

Variance Analysis

InstaSHAP explanations vary between runs due to random sampling

Var(φ̂ᵢ) = (1/k) × Var_S[f(S∪{i}) - f(S)] As k increases: k = 10: Var ≈ 0.015 (high uncertainty) k = 50: Var ≈ 0.003 (moderate) k = 200: Var ≈ 0.0008 (low) k = ∞: Var = 0 (exact)

Failure 1 · Interactions

Feature Interaction Failure

When features work TOGETHER, individual contributions are misleading

Root Cause: InstaSHAP assumes features contribute independently — interaction terms are NOT captured
Failure 1 · Example

Interaction Example: XOR Problem

The XOR Function

f(X₁, X₂) = X₁ XOR X₂ X₁=0, X₂=0 → f=0 X₁=0, X₂=1 → f=1 X₁=1, X₂=0 → f=1 X₁=1, X₂=1 → f=0 Individual features have ZERO marginal effect! But together they determine everything.

InstaSHAP says:

X₁
≈0
X₂
≈0

Reality:

Both features are CRITICAL — they jointly determine the output. InstaSHAP assigns ≈0 to both!

Completely misleading
Failure 1 · Why

WHY Interactions Break InstaSHAP

  • 1 Marginal contribution assumes additivity: φᵢ measures how i alone changes the output
  • 2 XOR/interaction effects are non-additive: f(S∪{i,j}) ≠ f(S∪{i}) + f(S∪{j}) - f(S)
  • 3 Random sampling misses critical pairs: With k ≪ 2ⁿ, joint coalitions may never be sampled
  • 4 No interaction terms in output: Standard SHAP values are per-feature, not per-pair

Impact

Any model with significant feature interactions (neural networks, polynomial features, attention mechanisms) will produce misleading InstaSHAP explanations.

Failure 2 · Non-linear

Non-linear Model Failure

Complex decision boundaries create unreliable explanations

Linear model

f(x) = w₁x₁ + w₂x₂ + b

✓ InstaSHAP works perfectly — marginal contributions are constant

  • 2 Feature importance is position-dependent in input space
  • 3 Random perturbation may push inputs to different activation regions
  • 4 Average marginal contribution becomes meaningless across regions

Failure 3 · LLMs

LLM / Transformer Failure

Language models have sequential dependencies that break feature independence

Why LLMs are problematic

  • 1 Token order matters: "not good" ≠ "good not"
  • 2 Attention is global: Every token attends to every other
  • 3 Masking tokens creates invalid inputs: "The [MASK] is happy" is out-of-distribution
  • 4 Features ≠ tokens: Meaning spans token boundaries

Example

Input: "The movie was not good" Sentiment: Negative (0.2) InstaSHAP masking: Mask "not": "The movie was good" → Sentiment: Positive (0.85) → φ("not") = 0.2 - 0.85 = -0.65 ✓ Mask "good": "The movie was not" → INVALID INPUT (incomplete) → Model output: random → φ("good") = UNRELIABLE ✗
Failure 3 · Attention

Attention Mechanism: Why Masking Fails

Self-Attention computes:

Attention(Q,K,V) = softmax(QK^T/√d) · V

Every token sees every other token. Masking one changes ALL attention scores.

Impact on InstaSHAP

Removing token i changes how ALL other tokens interact — the "marginal contribution" of i is entangled with global context. InstaSHAP cannot decompose this.

Verdict: InstaSHAP is fundamentally ill-suited for transformer-based models due to global attention interdependencies
Failure 4 · Dist. Shift

Distribution Shift Failure

When inference data differs from training data, perturbation baselines become invalid

Failure 4 · Mechanism

How Distribution Shift Breaks InstaSHAP

The Problem

  • 1 InstaSHAP replaces masked features with training data samples
  • 2 If inference data has shifted, training baselines are wrong
  • 3 Perturbed inputs fall in regions the model wasn't trained on
  • 4 Model predictions on perturbed inputs are unreliable

Example

Training: Income mean = $50K Inference: Income mean = $150K (new market) InstaSHAP masks Income → replaces with training sample ($50K) → Model sees ($150K → $50K) = huge drop → Overestimates Income importance → WRONG explanation!

The Fundamental Trade-off

InstaSHAP sacrifices exactness for speed. In benign cases, this works well. In adversarial cases, the explanations can be completely wrong.

InstaSHAP Works When:

  • ✓ Features are ~independent
  • ✓ Model is ~additive
  • ✓ Distribution is stable

InstaSHAP Fails When:

  • ✗ Strong feature interactions
  • ✗ Highly non-linear models
  • ✗ Distribution shift present
⚠️ Limitations

InstaSHAP Limitations Overview

1. Loss of Exactness

Monte Carlo approximation means values change between runs. No guarantees on error bounds.

2. Approximation Bias

Systematic underestimation of interaction effects and correlated feature groups.

3. Scalability Limits

For very large n, even k·n model calls become expensive. Vision models with 10K+ features still struggle.

4. Not Universal

Cannot handle sequential models, RL agents, or models with non-tabular inputs natively.

For ML models: k = 50 # samples perturbation = "marginal" Expected quality: Correlation: 0.85-0.95 MAE: 0.02-0.05 Speed: 20-100ms

✗ LLMs

LLMs: Why InstaSHAP Cannot Work

  • 1 Token granularity mismatch: SHAP operates on features, but meaning in LLMs spans multiple tokens
  • 2 Context dependency: Every token's meaning depends on ALL surrounding tokens
  • 3 Invalid perturbations: Random token masking creates nonsensical inputs
  • 4 Combinatorial explosion: LLMs have 100K+ vocabulary, making even sampling infeasible
  • 5 Alternative needed: Attention visualization, integrated gradients, or specialized LLM explainability frameworks
Verdict: Do NOT use InstaSHAP for LLMs — use attention maps, LIME for text, or specialized tools

🎯 Adaptive Sampling

Improvement 2: Adaptive Sampling

Sample more in important regions, less in unimportant ones

🎯 Adaptive Algorithm

Adaptive Sampling Algorithm

# Adaptive Sampling v2 1. Start with k₀ = 10 uniform random subsets 2. Compute initial φ̂ᵢ and variance estimates 3. For features with HIGH variance: → Sample MORE subsets (increase local k) 4. For features with LOW variance: → Stop sampling (converged) 5. Repeat until: → Total budget K exhausted, OR → All variances below threshold ε # Benefit: Same total K, but much better allocation # High-variance features get 5-10× more samples # Low-variance features get 2-3× fewer samples
🧠 Model-Aware

Improvement 3: Model-Aware Explanation

Use model internals to guide the sampling process

Current: Model-Agnostic

InstaSHAP treats the model as a black box. It doesn't use ANY information about model structure or gradients.

  • ✗ Wastes samples on irrelevant feature combinations
  • ✗ Cannot detect which features interact

Proposed: Model-Aware

Use gradient information or internal activations to guide which subsets to sample.

  • ✓ Gradients indicate feature sensitivity
  • ✓ Hessian reveals interaction pairs
🧠 Gradient-Guided

Gradient-Guided Sampling

# Model-Aware InstaSHAP v2 1. Compute gradient: ∇f(x) = [∂f/∂x₁, ∂f/∂x₂, ..., ∂f/∂xₙ] 2. Identify high-gradient features (sensitive features) 3. Compute Hessian diagonal: H = [∂²f/∂x₁², ..., ∂²f/∂xₙ²] 4. High curvature = non-linear effect → needs more samples Sampling allocation: kᵢ ∝ |∂f/∂xᵢ| × |∂²f/∂xᵢ²| (more samples for sensitive, non-linear features)
Trade-off: Requires ONE gradient computation (1 backward pass) but guides ALL subsequent sampling → net gain
